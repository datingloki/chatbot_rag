# S0 — бейзлайн-бот на интентах

Реализация S0 из design doc (6.1). Генеративной LLM нет: бот выбирает готовый ответ из FAQ
или предлагает консультанта. Главный показатель — **M17**: сколько доменных вопросов S0
направляет оператору. Рядом смотрим прокси M02–M06, чтобы неверный ответ не считался успехом.

## Порядок работы (бизнес-логика design doc)

1. **Вход и явный выход за домен.** Пустое сообщение или > 2000 символов → `reject_input`.
   Классификатор домена (`../domain_classifier`): только `out_of_domain` → `refuse`;
   `unclear` идёт дальше (S0 не умеет уточнять).
2. **Интент.** Интенты = **все 100 статей FAQ**, зафиксированные в
   [`intents/intents_v1.jsonl`](intents/intents_v1.jsonl) (см. «Интенты» ниже). 3 пары статей
   Полиграфия 2 / Полиграфия 8 с одинаковым текстом имеют общий `answer_key` (97 разных ответов).
3. **Уверенный интент** (P(интент) ≥ порога) → шаблон: текст статьи FAQ + источник (раздел, URL).
4. **Низкая уверенность, нет шаблона или клиент-специфичная проблема** → `offer_handoff`,
   без выдуманного ответа. Клиент-специфичность — правила в `s0.py` (`client_specific`):
   доработка/расширение, «наша/рабочая база», копия базы, филиал, журнал регистрации,
   ИНН/код партнёра/рег. номер, «вышлите счёт» и т. п.
5. **Передача** — только при согласии пользователя **и** подтверждённой интеграции
   (`INTEGRATION_CONFIRMED = False`: OmniDesk не подтверждён). Поэтому S0 заявку не создаёт
   и пишет «Автоматическая передача обращения пока не подтверждена» (design doc 2.2).

## Интенты

Интенты и шаблоны хранятся в версионированном файле `intents/intents_v<N>.jsonl`; бот и
`train.py` читают только его, `knowledge base/` после генерации на S0 не влияет.

- Файл создаётся один раз из FAQ: `.venv/bin/python build_intents.py` (источники —
  `knowledge base/faq_articles.jsonl` и `faq_license_install_articles.jsonl`, перефразы — dev).
  Существующий файл без `--force` не перезаписывается; новая версия — `--version v2`.
- Строка = интент: `intent_id`, `title`, `answer_template` (текст ответа бота), `source_title`,
  `source_url`, `answer_key`, `examples` (`faq_title`, `faq_title_answer`, `dev_paraphrase` с
  `case_id`/`group`), `status` (`draft` → `approved`), `approved_by`, `approved_at`,
  `source_faq_file`, `source_sha256`.
- Консультант утвердил все 100 интентов, порог и шаблоны (подтверждено командой 19.11.2026).
  В самом файле `intents_v1.jsonl` поле `status` пока `draft`: его смена меняет sha256 файла,
  после неё нужно перезапустить `train.py`.
- `model/s0.joblib` хранит путь, версию и sha256 файла интентов. Если файл изменили после
  обучения (даже статус), бот не запустится — нужно перезапустить `train.py` (порог
  подбирался для конкретного набора примеров).
- Векторы примеров (TF-IDF и MiniLM) считаются в `train.py` и лежат в `s0.joblib` (~3.4 МБ);
  при запуске бот кодирует только входящее сообщение.

## Модель

План в design doc: TF-IDF + линейный классификатор. На dev он проигрывает поиску ближайшего
прототипа (у интента 1 заголовок и несколько перефраз — линейной модели не на чем учиться):

| Вариант (dev, 21 перефраза FAQ / 216 доменных без FAQ) | top-1 по перефразам | Найдено перефраз при 2–5 % ложных ответов |
|---|---|---|
| TF-IDF (символы + леммы) + LogisticRegression, C=100 | 0.52 | 0.05–0.10, 3 неверных FAQ |
| сходство: char TF-IDF | 0.71 | 0.33–0.38 |
| сходство: MiniLM | 0.62 | 0.14–0.24 |
| сходство: lemma + MiniLM | 0.81 | 0.43–0.52 |
| **сходство: char + lemma + MiniLM (выбрано)** | 0.76 | 0.29–0.52, 0 неверных FAQ |

- **Примеры интента** (поле `examples` в файле интентов): заголовок FAQ; заголовок + первые
  400 символов ответа; перефразы FAQ из dev (21 шт.).
- **Сходство** = среднее косинусов трёх представлений: TF-IDF по символьным 2–5-граммам,
  TF-IDF по леммам pymorphy3, эмбеддинг `paraphrase-multilingual-MiniLM-L12-v2` (ONNX
  через fastembed, открытые веса, CPU, без API — C12). Берём максимум по прототипам интента.
- **Уверенность:** логистическая регрессия P(топ-1 интент верный | сходство, отрыв от ближайшего
  интента с другим ответом), обучена на dev.
- **Порог** подобран на dev по out-of-fold вероятностям (GroupKFold по `split_group_id`;
  перефразы своей группы исключаются из прототипов): минимальный порог, при котором шаблоном
  отвечаем не более чем на 3 % доменных вопросов без FAQ и не выдаём неверный FAQ. Сейчас
  **0.3955**. Результат в `model/train_report.json`.
- Mpnet-base отброшен: на CPU ноутбука Марии эмбеддинги слишком медленные (> 20 мин на dev).
- Многоходовый диалог: интент по текущему сообщению; если не уверен — повторно вместе с
  предыдущими сообщениями пользователя.

## Данные и разделение

- Используются **только база знаний и dev**. `train.py` eval не читает.
- Обучающих обезличенных обращений, отдельных от dev/eval, пока нет (design doc 6.1), поэтому
  «обучение» S0 — это заголовки FAQ + перефразы из dev, а калибровка и порог — тоже dev.
- **Важно для eval:** в eval 38 кейсов — дословные заголовки FAQ (`official_faq_entry`). Заголовок —
  прототип интента, поэтому эти кейсы S0 решает тривиально. В отчёте есть M17 и покрытие FAQ
  без них (`M17_without_verbatim_faq_titles`, `paraphrases_answered_correctly`).

## Ограничения

- Шаблоны = тексты FAQ «как есть»; список интентов, порог и шаблоны утверждены консультантом.
  Длинные статьи (до 20 тыс.
  символов) показываются целиком.
- Правила клиент-специфичности подобраны по dev; на dev они ловят все K6 и 15/33 K4 (остальные
  K4 уходят оператору по низкой уверенности) и не блокируют ни одного FAQ-кейса.
- M01, M03 (полнота против `must_include`), M07, M08, M10 требуют ручной проверки: построчные
  результаты — `results/<set>_cases.jsonl`. Тексты бота фиксированы, поэтому M07/M08 для отказа
  и передачи достаточно проверить один раз.
- В наборах нет кейсов с тегами рисков/injection, поэтому M10 кодом не считается.

## Запуск

```bash
cd s0_baseline
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python build_intents.py        # только если intents/intents_v1.jsonl ещё нет
.venv/bin/python train.py                # порог, калибровка и векторы примеров → model/s0.joblib (~4 мин)
.venv/bin/python evaluate.py --set dev   # → results/dev_report.json, results/dev_cases.jsonl
.venv/bin/python evaluate.py --set eval  # только на замороженной модели
.venv/bin/python s0.py "Какой срок действия лицензии на программу?"
```

При первом запуске MiniLM (~240 МБ) скачивается в `s0_baseline/models/` (в git не попадает).
Нужен также `../domain_classifier/model/domain_clf.joblib`.
