# Классификатор выхода из домена

Первичная маршрутизация (дизайн-док, 2.2): сообщение → `in_domain` / `out_of_domain` / `unclear`.
Положительный класс — K1 (`out_of_domain`), остальные K2–K6 — домен.

**Обучение только на `dev set/dev_300_balanced.jsonl`.** Eval-сет скрипты не читают.

## Модель

- Признаки: TF-IDF по леммам pymorphy3 (1–2-граммы) + TF-IDF по символьным 2–5-граммам + усреднённые векторы navec (`navec_news_v1_1B_250K_300d_100q`, поставляется с natasha). Классификатор обучается с нуля на dev; единственная предобученная часть — замороженные векторы navec (открытые веса, без API, C12).
- Классификатор: LogisticRegression, `class_weight=balanced`, C=16.
- Кейсы с тегом `domain_unclear` (K3: неясно, о программе ли вопрос) не входят в обучение и подбор порогов: для них правильный ответ маршрутизатора — `unclear`. Они проверяются отдельно.
- Пороги по out-of-fold вероятностям dev, с допусками:
  `t_out` — минимальный порог, при котором ложных отказов доменным вопросам ≤ 1% (C05);
  `t_in` — максимальный порог, при котором принятых как доменные посторонних ≤ 2%.
  Сейчас: `p < 0.27` → `in_domain`, `0.27 ≤ p < 0.72` → `unclear`, `p ≥ 0.72` → `out_of_domain`.
- В многоходовом диалоге решение принимается по текущему сообщению; если оно `unclear`, оно оценивается повторно вместе с предыдущими сообщениями пользователя.
- Поверх модели — слой правил ([rules.py](rules.py)), по словарям лемм. Правила не отказывают по одному слову, а только корректируют решение модели:
  - **R1 domain_term**: модель отказывает, но есть термин продукта или сопровождения (1С, ИТС, КП, СЛК, лицензия, релиз, техподдержка, консультация…) и нет признаков проф. консультации → `unclear`;
  - **R2 short_ambig**: короткое сообщение (≤ 4 значимых слов) с объектом, который есть в программе (принтер, отчёт, зарплата, штрихкод…) → `unclear` вместо отказа;
  - **R3 prof_consult**: признаки юридической/налоговой/кадровой консультации («закон», «ТК», штраф, суд, увольнение, налог, УСН…) без указания на программу → `out_of_domain`;
  - **R4 third_party**: модель не уверена (`unclear`), названо стороннее ПО/сервис/устройство (Word, Excel, Zoom, Telegram, Photoshop, Android, роутер…), и нет терминов продукта, указания на программу и интеграций из базы знаний (Битрикс24, Манго, Касперский, MS SQL, RDP, Mac…) → `out_of_domain`. Решение модели `in_domain` R4 не меняет.
  - **R5 install_no_obj**: модель отказывает, но это вопрос об установке или скачивании без объекта («Как поставить на компьютер?», «Поставить на второй компьютер») — что ставить, не сказано, и это может быть программа → `unclear`. С объектом («установить Python», «установить Windows») не срабатывает. На dev решений не меняет (добавлено 18.11.2026 по живому тесту бота).
  `predict()` возвращает итоговый `label`, а также `model_label` и сработавшее `rule`; `use_rules=False` отключает правила.

## Ограничения (важно)

- **ИТ-пары добавлены только в dev** (30 посторонних ИТ-вопросов + 15 доменных ИТ-двойников с источниками). Темы, уже представленные в eval (Outlook, CorelDRAW, выбор антивируса, SQL-запросы, CRM), не использовались, и эти названия не включены в словарь R4 — eval остаётся проверкой обобщения на незнакомое ПО.
- **Правила подобраны по dev.** «Консультация» (R1) и «налог», «УСН», «ОСНО» (R3) добавлены после разбора ошибок на dev. Пограничные кейсы dev и eval написаны одним автором, поэтому eval — не полностью независимая проверка словарей.
- **Вопросы о поддержке в основном уходят в `unclear`**, а не в `in_domain`: отказа нет, но вместо ответа (по эталону K2) бот задаст уточнение.
- **Цель M04 ≥ 95% не достигнута:** 85% сразу корректных отказов; 15 посторонних остаются `unclear` (уточнение): 6 пограничных (2 проф. консультации, 2 с упоминанием 1С, 2 общая ИТ) и 9 исходных бытовых K1.
- Пограничные кейсы синтетические и в статусе `draft` (не проверены консультантом).
- Пороги подобраны на тех же кейсах dev (OOF); их нужно перепроверить на отдельных данных.
- Ручные примеры в `train.py` (`PROBES`) — только для качественной проверки; не совпадают с кейсами eval.

## Запуск

```bash
cd domain_classifier
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python train.py                                   # CV + финальная модель в model/
.venv/bin/python domain_clf.py "Подскажи рецепт борща"      # предсказание
```

                                     {"role": "assistant", "text": "В каком документе?"}])
