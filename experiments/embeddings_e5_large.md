# Эксперимент: модель эмбеддингов `multilingual-e5-large` вместо MiniLM

Задача для исполнителя на один заход: собрать индекс базы знаний с другой dense-моделью в **отдельную** коллекцию, прогнать оценку поиска на dev и вернуть таблицу «до → после». LLM, ключи провайдера и Telegram не нужны.

Владелец решения — Мария Кащеева. Результат идёт строкой 6 в раздел 8.2 `design_doc_KT-3.md`.

---

## 1. Контекст: что за система и зачем эксперимент

**Система.** Чат-бот поддержки по 1С:Полиграфии (RAG). На вопрос пользователя бот ищет фрагменты в базе знаний и по ним генерирует ответ со ссылкой на источник. Код — `bot/`, подробности — `bot/README.md` и `design_doc_KT-3.md` (разделы 4.2, 4.3, 8.2).

**База знаний** (`knowledge base/`, в git) — 4 305 фрагментов:

| Источник | Фрагментов |
|---|---:|
| FAQ сайта 1cpoly.ru (100 статей) | 260 |
| Руководство «УНФ 8. Полиграфия 2», ред. 3.0 (314 разделов) | 811 |
| Архив ответов поддержки OmniDesk (1 292 обращения) | 3 234 |

**Как устроен поиск сейчас** (`bot/polybot/clients/qdrant_retriever.py`, настройки — `bot/polybot/settings.py`, класс `RetrievalSettings`):
- dense — `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (384, fastembed/ONNX, CPU);
- sparse — BM25 по леммам и отдельный BM25 по заголовкам разделов;
- слияние — взвешенный RRF (k = 60; веса dense 1, BM25 2, заголовки 1);
- квота: не больше 2 фрагментов OmniDesk в топ-5, официальные источники и архив ищутся отдельно;
- Qdrant в локальном режиме (папка `bot/data/qdrant_local`), рабочая коллекция `polygraphy_kb`.

**Проблема, которую проверяем.**
1. Dense-часть слабая: в режиме «только dense» руководство находится в 36 из 125 случаев, а BM25 — в 83. Отчасти поэтому BM25 получил вес 2.
2. MiniLM обучена на входе до 128 токенов и обрезает фрагменты: у 72 % фрагментов текст длиннее, медиана — 178 токенов, то есть вектор видит в среднем ≈ 72 % текста.
3. Поднять лимит MiniLM до 256 токенов уже пробовали 20.11.2026 — поиск стал **хуже** (руководство hit@5 101 → 95). Модель не умеет сворачивать в вектор вход длиннее того, на котором её обучали. Значит, нужна модель, обученная на длинном входе и на задаче поиска.

**Гипотеза.** `intfloat/multilingual-e5-large` (1024, лимит 512 токенов, обучена на поиск «вопрос → документ», русский поддерживается) поднимет dense-поиск, особенно по руководству и перефразам FAQ, и даст рост hit@5 в гибриде.

**Что проверяем:**
- качество поиска на dev: hit@1, hit@5, MRR@10, раздел@5 — в гибриде и в режиме «только dense»;
- задержку эмбеддинга одного запроса (сейчас ≈ 15 мс) и P50/P95 поиска целиком;
- время сборки индекса и потребление памяти.

Отчёты: `bot/harness/results/retrieval_20261118_163010.json` (гибрид), `retrieval_20261120_121619.json` (только dense).

|---|---:|---:|---:|---:|

| Перефразы FAQ (21) | 14 | 19 | 19 | 17 |
| Руководство (125) | 57 | 101 | 107 | 36 |

Гибрид: MRR@10 — FAQ дословно 0,987, перефразы 0,792, руководство 0,594. Поиск P50 / P95 — 0,90 / 1,73 с. Сборка индекса — 226 с.

## 3. Правила (обязательно)

- **Eval не трогать.** Файл `eval set/eval_300_balanced.jsonl` закрыт до КТ4: не открывать, не запускать по нему скрипты, не ставить `HARNESS_ALLOW_EVAL=1`. `harness.retrieval_eval` работает только по dev — так и нужно.
- **Рабочую коллекцию `polygraphy_kb` не пересобирать и не удалять.** Всё — в новую коллекцию `polygraphy_kb_e5l` через переменные окружения (ниже). `bot/.env` не редактировать.
- **Не коммитить в `main`.** Отчёты и правки — в ветку `exp/e5-large` от `kt3`, либо просто прислать файлы.
- Пока идёт сборка или оценка, бот и другие скрипты с локальным Qdrant не запускать: локальный Qdrant открывает только один процесс.

## 4. Что нужно до начала

- Доступ к репозиторию `datingloki/chatbot_rag`, ветка `kt3` **с последними правками Марии** (в них есть настройка `RETRIEVAL__DENSE_MAX_TOKENS` — без неё e5 будет обрезан до 128 токенов).
- Python 3.12, около 6 ГБ свободного места на диске (модель 2,24 ГБ + индекс), желательно 8+ ГБ RAM.
- Интернет для разовой загрузки модели с Hugging Face (fastembed скачивает её сам в `bot/models/`).
- Время: загрузка модели — минуты; сборка индекса — по грубой оценке 1–2 часа на CPU ноутбука (модель примерно в 10 раз тяжелее MiniLM); оценка — около 10 минут на режим.

Если исходные цифры из раздела 2 у вас воспроизводятся (`.venv/bin/python -m harness.retrieval_eval --note "baseline MiniLM"`), сравнение честное.

### 5.2. Сборка индекса с e5-large

Переменные окружения перекрывают `.env`, поэтому рабочий индекс не затрагивается. Все команды разделов 5.2–5.4 выполнять **в одном окне терминала** после этих трёх строк:

```bash
export RETRIEVAL__DENSE_MODEL=intfloat/multilingual-e5-large
```

```bash
export RETRIEVAL__DENSE_MAX_TOKENS=512
```

```bash
export RETRIEVAL__COLLECTION=polygraphy_kb_e5l
```

```bash
/usr/bin/time -l .venv/bin/python -m ingest.build_index 2>&1 | tee e5_build.log
```

`/usr/bin/time -l` (macOS) в конце печатает `maximum resident set size` — это пиковая память; на Linux — `/usr/bin/time -v`, строка `Maximum resident set size`. Записать время сборки из последней строки скрипта и пиковую память.

Проверить, что в манифесте `bot/data/polygraphy_kb_e5l.manifest.json` стоят `"dense_model": "intfloat/multilingual-e5-large"`, `"dense_max_tokens": 512` и `"dim": 1024`.

Префиксы `query:` / `passage:`, которые нужны моделям e5, энкодер добавляет сам (`polybot/retrieval/encoders.py`, по слову `e5` в имени модели).

### 5.3. Оценка поиска на dev

Гибрид с текущими весами:

```bash
.venv/bin/python -m harness.retrieval_eval --note "e5-large 512, hybrid bm25_weight=2 title_weight=1 omnidesk_k=2"
```

Только dense — эффект самой модели без RRF:

```bash
RETRIEVAL__MODE=dense .venv/bin/python -m harness.retrieval_eval --note "e5-large 512, dense only"
```

Веса RRF подбирались под слабый MiniLM. Если гибрид с e5 вырос, проверить вес BM25 1 (при сильном dense BM25 может перевешивать):

```bash
RETRIEVAL__BM25_WEIGHT=1 .venv/bin/python -m harness.retrieval_eval --note "e5-large 512, hybrid bm25_weight=1"
```

Каждая команда печатает таблицу и путь к отчёту `harness/results/retrieval_<время>.json`. В конце вывода — таблица порогов `evidence_gate` (доля кейсов с косинусом лучшего фрагмента ≥ порога). У e5 косинусы распределены иначе, чем у MiniLM (обычно все выше), поэтому текущий порог `min_score=0.5` для неё, скорее всего, не подходит; таблицу порогов приложить обязательно.

### 5.4. Задержка эмбеддинга запроса

```bash
.venv/bin/python - <<'EOF'
import json, statistics, time
from polybot.settings import Settings
from polybot.retrieval.encoders import DenseEncoder
cfg = Settings().retrieval
enc = DenseEncoder(cfg.dense_model, cfg.models_dir, cfg.dense_max_tokens)
qs = [json.loads(l)["input"]["user_message"] for l in open("../dev set/dev_300_balanced.jsonl")][:100]
enc.query("прогрев")
ts = []
for q in qs:
    t = time.perf_counter(); enc.query(q); ts.append((time.perf_counter() - t) * 1000)
ts.sort()
print(f"эмбеддинг запроса: P50 {statistics.median(ts):.0f} мс, P95 {ts[int(len(ts) * 0.95)]:.0f} мс, max tokens {enc.max_tokens}")
EOF
```

Для сравнения у MiniLM — ≈ 15 мс.

## 7. Как читать результат (для решения)

- **Берём e5**, если в гибриде руководство hit@5 выше 101/125 и перефразы FAQ не ниже 19/21 без падения FAQ дословно; задержка эмбеддинга запроса — до ≈ 0,3 с (бюджет хода — P95 15 с, дедлайн 25 с).
- **Не берём**, если рост в пределах 1–3 кейсов: на 125 и 21 кейсе это шум (95 % ДИ доли на 21 кейсе — около ±20 п. п.).
- Если e5 сильно лучше в «только dense», но гибрид не вырос, — следующий шаг: подбор весов RRF под новую модель.
- В любом случае: для бота придётся пересобрать рабочий индекс, подобрать `min_score` по таблице порогов и учесть 2–3 ГБ RAM на модель на сервере пилота (4.6).

## 8. Известные подводные камни

- fastembed при загрузке MiniLM предупреждает о смене пулинга (mean вместо CLS). Для e5 может быть похожее предупреждение — записать его текст.
- Если сборка падает по памяти, уменьшить батч: `--batch 16` в команде `ingest.build_index`.
- Если `harness.retrieval_eval` пишет, что индекс собран с другим `dense_max_tokens` или другой моделью, — команда запущена в окне без трёх `export` из 5.2.
- После эксперимента, чтобы вернуться к рабочему индексу в том же окне: `unset RETRIEVAL__DENSE_MODEL RETRIEVAL__DENSE_MAX_TOKENS RETRIEVAL__COLLECTION` (или открыть новое окно).
- Ошибка про занятый Qdrant — работает другой процесс с локальным Qdrant (бот, харнесс); остановить его.
