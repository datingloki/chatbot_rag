## Контекст

Поиск — гибрид dense + BM25 + BM25 по заголовкам с взвешенным RRF (4.3). Dense-часть слабая: в режиме «только dense» руководство находится в 36 из 125 кейсов dev, а BM25 — в 83; поэтому BM25 получил вес 2. Текущая модель `paraphrase-multilingual-MiniLM-L12-v2` обучена на входе до 128 токенов: у 72 % из 4 305 фрагментов текст длиннее (медиана — 178 токенов), и вектор видит в среднем ≈ 72 % текста (замер 20.11.2026). Ограничения: CPU без GPU (4.6), задержка поиска входит в бюджет хода (P95 15 с, дедлайн 25 с), русский язык.

## Рассмотренные варианты

| Вариант | Качество на dev (гибрид, hit@5) | Задержка и ресурсы | Статус |
|---|---|---|---|
| A. **MiniLM, 128 токенов** (сейчас) | FAQ дословно 38/38, перефразы 19/21, руководство 101/125, раздел@5 107/125 | Эмбеддинг запроса ≈ 15 мс; сборка индекса 226 с; 0,22 ГБ | Рабочий индекс |
| B. **MiniLM, лимит 256 токенов** | Хуже: руководство 101 → 95, hit@1 57 → 42; FAQ дословно 38 → 37; «только dense» — руководство 36 → 31 | Сборка 537 с | Отклонён 20.11.2026 (8.2, строка 5) |
| C. **`intfloat/multilingual-e5-large`**, 512 токенов: обучена на поиск «вопрос → документ», 1024 измерения | Не измерено | Модель 2,24 ГБ; по грубой оценке сборка 1–2 часа, эмбеддинг запроса 0,1–0,3 с — не измерено | Эксперимент идёт (`experiments/embeddings_e5_large.md`) |
| D. **Короче фрагменты для dense** (≈ 450 символов), BM25 по всему фрагменту | Не измерено | Индекс больше по числу векторов | Кандидат на КТ4 |

## Решение

Пока не принято. Рабочим остаётся A. Критерии выбора C (из инструкции к эксперименту):
- в гибриде руководство hit@5 выше 101/125, перефразы FAQ не ниже 19/21, FAQ дословно не падает;
- эмбеддинг запроса до ≈ 0,3 с;
- рост больше 1–3 кейсов: меньший рост на 125 и 21 кейсе — шум.

Если C сильно лучше в «только dense», а гибрид не вырос, — следующий шаг: подбор весов RRF под новую модель.

## Последствия (если выберем C)

- Пересобрать рабочий индекс; подобрать порог `evidence_gate` (`min_score`) заново — у e5 другое распределение косинусов; при необходимости — веса RRF (8.2).
- Учесть 2–3 ГБ RAM на модель на сервере пилота (4.6) и задержку эмбеддинга в 3.2.
- Прогнать dev целиком (M01, M17) — рост hit@5 не гарантирует роста качества ответов.
