# ADR-003: Интент-бот S0 по статьям FAQ как baseline

| | |
|---|---|
| Статус | принят |
| Дата | 20.11.2026 |
| Авторы | Елизавета Гапонова, Кащеева Мария |
| Связано | design doc: 7.2 (M01, M17), 8.1 (baseline), 8.2; ADR-001 (вариант E) |

## Контекст

Систему с поиском и генерацией надо сравнивать с чем-то измеренным на тех же кейсах и тем же харнессом (5.4). Главный показатель ценности для сравнения — M17: какую долю доменных вопросов система оставляет оператору. Без LLM у заказчика уже есть FAQ на сайте (100 статей) и консультанты; простая автоматизация, которую можно сделать без генеративной модели, — бот, который узнаёт вопрос и отдаёт готовую статью.

## Рассмотренные варианты

| Вариант | Что показывает | Стоимость и риски |
|---|---|---|
| A. **Интент-бот S0**: классификатор домена + сопоставление вопроса со 100 статьями FAQ, ответ — текст статьи, ниже порога уверенности — оператор | Что даёт автоматизация без LLM: M17, отказ вне домена, точность готовых ответов. Ответы — утверждённые консультантом тексты, поэтому M01 считается без ручной проверки текста (7.2) | 0 ₽ за ход, P50/P95 28/72 мс; не зависит от доступа к модели |
| B. **Одна LLM с промптом, без поиска** | Что даёт модель без базы знаний | Ответы без источника нарушают C03 по построению; зависит от доступа к модели. Не реализован |
| C. **Минимальный RAG только по FAQ** | Что даёт поиск по FAQ с генерацией | Зависит от доступа к модели; сравнивает RAG с RAG, а не с автоматизацией без LLM. Не реализован |

## Решение

Выбрали **A — интент-бот S0**. Это честная планка «что можно сделать без генеративной модели» по тем же статьям FAQ, на которых отвечает и RAG, и он измерен на dev тем же харнессом: M01 = 262/388 (+2 на ручную проверку), M17 = 213/275 (77,5 %), уточнение 0/49, P50/P95 28/72 мс, 0 ₽ (8.1). Вариант B нарушает контракт C03 и не измерим без модели; C не отвечает на вопрос, нужна ли LLM вообще.

## Последствия

- Плюсы: baseline есть уже сейчас, несмотря на блокировку ключа; одна команда харнесса для S0 и RAG (`harness.run --system s0|rag`); улучшение M17 засчитывается только без регрессии M03, M06, M10 (8.1).
- Минусы: числа S0 на dev оптимистичны — интенты, калибровка и порог подобраны на dev (out-of-fold: верный FAQ для 4 из 21 перефразы, 8.1); S0 не отвечает по руководству и архиву, поэтому на кейсах руководства сравнение заведомо в пользу RAG.
- Что нужно сделать: прогнать S0 и RAG на eval один раз на КТ4;
- При каких условиях пересматриваем: найдется способ дешево сделать другой baseline, который будет полноценно  отражать работу консультантов.
