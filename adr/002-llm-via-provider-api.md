## Контекст

Боту нужна генеративная модель с хорошим русским и ответом в JSON по схеме, один вызов на сообщение (ADR-001). Нагрузка пилота — до 30 обращений и до 180 сообщений в день, ≈ 0,02 RPS в пиковый час (1.2). Сервер бота — один, без GPU (4.6). Сообщения пользователей могут содержать персональные и коммерческие данные (C08), поэтому провайдер вне РФ создаёт проблему с 152-ФЗ (10.3). Бюджет — грант Yandex AI Studio на разработку и пилот (3.3).

## Рассмотренные варианты

| Вариант | Качество | Задержка | Стоимость | Что ещё |
|---|---|---|---|---|
| A. **API Yandex AI Studio**, Qwen3.6 35B A3B, `json_schema` | Dev ×3: M01a 926/1164 (79,6%), M05r 129/147 (87,8%), M06r 232/279 (83,2%); ручная M03/M07/M08 не утверждена | Харнесс P50/P95 3,07/5,04 с, без доставки Telegram | 361,471 ₽ за 1164 хода, 0,311 ₽/ход по настроенным тарифам | Доступ работает 22.11; исторический инцидент 19.11 остаётся риском доступности |
| B. **Своя модель на сервере с GPU** (vLLM / Ollama) | Зависит от модели, которая поместится в арендованную GPU; не измерено | Не измерено | Аренда сервера с GPU не оценивалась | Нужен сервер с GPU — в 4.6 его нет; эксплуатация модели на команде. Данные не уходят провайдеру |
| C. **Своя модель на CPU** (Ollama, например `qwen3:8b`) | Меньшая модель; по оценке в 10.2 качество хуже — не измерено | По оценке в 10.2 хуже — не измерено | Без платы за токены, только сервер | Запасной вариант на случай недоступности API: клиент уже поддерживает Ollama через тот же OpenAI-совместимый интерфейс (`LLM__BASE_URL`, `.env.example`) |
| D. **Зарубежный API** | Не рассматривали по качеству | — | — | Передача данных провайдеру вне РФ (10.3) — отклонён до сравнения |

## Решение

Выбрали **A — API Yandex AI Studio**. Решающими были стоимость сервера с GPU vs сервер без GPU, провайдер в РФ для данных пользователей (C08, 10.3) и грант, который покрывает вызовы на разработке и пилоте. При нагрузке ≈ 0,02 RPS держать свой инференс ради нескольких сотен вызовов в день нет смысла. Клиент LLM написан под OpenAI-совместимый протокол, поэтому переход на B или C — это смена `LLM__BASE_URL` и модели в `.env`, без изменений графа.

## Последствия

- Плюсы: нет своей GPU-инфраструктуры; стоимость хода предсказуема и ограничена одним вызовом; модель пиннится полным URI, версия — в `meta.json` прогона (4.4).
- Минусы: зависимость от провайдера и ключа; после инцидента 19.11 доступ работает 22.11. Замаскированные данные передаются провайдеру; модель может исчезнуть из каталога. Сквозной dev уже измерен, но итоговое качество ответов не утверждено.
- Что осталось: ручная оценка и разбор расхождений M03/M07/M08, разбор ошибок в двух диалогах K5, сравнение с Pro 5.1 на dev на КТ4. Закрытый Eval до КТ4 не использовать.
- Пересматриваем при повторной длительной недоступности API, недостаточном качестве после содержательной оценки или изменении стоимости/нагрузки. Доступ восстановлен; срочный переход на CPU только из-за прежней блокировки сейчас не требуется.
